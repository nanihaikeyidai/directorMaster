# MiniMax H3 时序工程规范

本文件定义 H3 分支的拆分、时长预算与校核方法。它解决的不是“如何把台词切得更碎”，而是如何让每个独立 `H3_UNIT` 有完整的动作、表演呼吸和可剪辑的头尾。长剧本先按 [MINIMAX_H3_LONG_SCRIPT_UNITS.md](MINIMAX_H3_LONG_SCRIPT_UNITS.md) 建立全文单元蓝图，再在这里校核每段真实承载量。

## 一、先做时间预算，再决定片段边界

在写任何 H3 提示词前，先按 [MINIMAX_H3_SCENE_GROUNDING_AND_RUNTIME.md](MINIMAX_H3_SCENE_GROUNDING_AND_RUNTIME.md) 提取剧本/用户声明的全片时长，建立逐场 `RUNTIME_BUDGET`；再按 [MINIMAX_H3_SOURCE_COVERAGE.md](MINIMAX_H3_SOURCE_COVERAGE.md) 建立原剧本 `SOURCE_BEATS` 与连续道具 `PROP_STATE_CHAIN`，同时计算口播承载量和可见动作承载量。为每句可听见的中文计算：

- 普通自然对白：每秒 4.0–4.5 个汉字，默认 4.25。
- 放慢的情绪旁白、压抑独白或带较长停顿的回忆：每秒 2.5–3.0 个汉字，默认 3.0。
- 标点不计入汉字数，但逗号、破折号、省略号、吞咽、看向对方等必须预留可见或可听见的停顿。

计算：

`口播秒数 = 可听见汉字数 ÷ 语速`

`镜头秒数 = 口播秒数 + 0.3–0.5 秒开场建立 + 0.3–0.8 秒收束/反应 + 独立片段需要的剪辑余量`

另行计算：

`可见动作最低秒数 = 环境建立 + 动作起点 + 状态变化 + 结果可读时间 + 必要转场`

对白与动作可以在真实可读的情况下重叠，但不能假设所有动作都能藏在口播时间里。片段时长必须满足二者合成后的完整时间线。环境空镜之后的人物入场、屏幕数值或文字揭示、手表等细节闪现、以及道具的拿起/关闭/放下/掉落/捡回等状态改变，都必须获得可读时间。

不要因为一句话短就将镜头缩成急促切片；短句可由对视、动作余波或环境声完成表演时长。相反，当完整台词、可见动作、道具状态变化与必要停顿无法安全放入一个 H3 片段时，先选择更长时长，再在自然边界处分段，绝不压缩、删改台词，也不得把多个剧本动作概括成一个模糊动作。

对白、关系、日常和轻喜剧单元同时遵守文戏密度预算：10 秒建议 16–24 个有效字符，12 秒建议 20–30 个，15 秒建议 26–36 个；任何中文文戏单元不得超过 40 个有效字符。有效字符只统计实际发声的汉字、字母和数字。迟疑、哽咽、爆发、长停顿或复杂动作使建议上限再降低约 20%。字数预算与语速估时必须同时通过，不能用其中一个替代另一个。

完成逐场预算后，必须汇总全部片段。若源码忠实最低时长或打包总时长超过声明全片时长 5% 以上，立即停止全片提示词生成，向用户展示声明时长、最低时长、拟打包时长、超出秒数及造成冲突的台词/动作，并取得“延长成片、改编删减、或批准其他语速范围”中的明确选择。不得只检查每段不超过 15 秒而忽略全片总时长。

## 二、H3 片段的结构约束

- H3 单段为一个独立 `H3_UNIT`。对白与叙事场景默认 10–15 秒，优先选择 10、12、15 秒；15 秒包含稳定尾幅，不允许把台词和新动作塞到最后一帧。5–9.99 秒只用于长剧本规范允许且写明 `duration_exception_reason` 的极短终止场、转场、首尾帧任务或非文戏动作；任何单元不得超过 15 秒。
- 独立片段尽量预留 0.5 秒稳定头部余量和 0.8–1.0 秒稳定尾部余量。尾部余量内不得继续推镜、开始新动作或重置表情。完整台词和动作塞满时长而只剩 0.3 秒左右尾幅，必须明确标为不可安全剪辑并延长或重分片段。
- 分开记录提示词 `requested_duration`、平台 `supported_duration` 和下载成片 `observed_duration`。平台额外生成的帧只有在画面稳定时才能算剪辑余量。
- 镜头密度按单元时长规划：10 秒通常 2–3 镜，12 秒 3–4 镜，15 秒 3–5 镜，但这只是密度上限参考，不能为了达标制造无意义切镜。若表演、观察或连续行动的力量来自“不切”，允许整个 10–15 秒单元使用导演性单镜；若短建立、插入、反应细节或匹配切画面提供必要新信息，允许它在多镜单元中短至 0.5–2.5 秒。两类选择都必须写明戏剧理由。
- 一个内部镜头只承载一个主要**注意力目标**和一个完整可读的行动进程，注意力目标可以是人物、道具，也可以是人物关系。双人镜头、过肩镜头和分层构图可以同时容纳多人，只要人物距离、权力关系或听者反应就是该镜头的叙事主体，并明确谁主导注意、谁清晰或可辨认地虚化、前景遮挡、左右位置、眼线和反应时机。
- 一个 H3 片段不得跨越场景边界（地点、时间、现实/闪回层级）。同一地点内若情绪目标或行动目标已经改变，也应成为新片段。
- 每个单元必须列出其拥有的 `source_beat_id`。环境建立、人物入场、可见文字或后期节点的底图/时机/反应、道具状态改变等可以是同一单元中的内部镜头，但不能无主、重复改义或仅存在于 HTML 剧本文字栏。

这里的“镜头”是 `H3_UNIT` 内的内部摄影节拍，而不是机械地把每句台词拆为一个 H3 文件。只在自然停顿、行动阶段、关系变化、情绪转折、信息转折或场景变化处建立独立单元边界。

## 三、切分优先级

当台词或动作超出安全时长时，按以下顺序找切点：

1. 原剧本已有的句号、逗号、破折号、省略号和语义停顿；
2. 可见行动的阶段变化，例如“拿起纸 → 写下 → 折成 → 放飞”；
3. 情绪方向改变，例如“防备 → 承认”“压抑 → 崩溃”“误解 → 理解”；
4. 新信息落地并需要反应的瞬间；
5. 地点、时间或闪回层级切换。

禁止按换行、每句对白或每个词机械分段；也禁止把两个地点、两个时间层或两个独立情绪高潮硬塞进同一片段。

## 四、连续性设计

先读取 [MINIMAX_H3_CROSS_CLIP_EDIT_CONTINUITY.md](MINIMAX_H3_CROSS_CLIP_EDIT_CONTINUITY.md)。整场先建立 `SCENE_SHOT_LADDER`，再对每一对相邻独立片段共同建立 `CLIP_BOUNDARY_LEDGER`。每个边界只能选择一个主要策略：`exact_match_continuation`、`contrast_cut`、`neutral_bridge` 或 `scene_transition`。

每个拆开的 H3 片段都要有可执行的衔接说明。可采用：

- 前段末帧与后段首帧的同一物件、姿势、视线或构图锚点；
- 延续未完成动作，例如手仍压在纸鹤、门仍半开、人物仍在转身；
- 延续空间与方向，例如人物保持同一站位、移动方向、左右关系；
- 声桥，例如雨声转为监护仪、脚步声跨切；
- 明确的视觉匹配切，例如墨点湿痕切到病床白布。

禁止把前一段的 `exit_state` 和后一段的 `opening_state` 分别写完就视为通过。必须并排比较两侧的景别/裁切、人物占比、机位/主轴、屏幕位置、视线、动作阶段、道具状态、相机运动、光位、嘴部、情绪和声音。同一主体、同一轴线、相近景别但画面大小或姿势重置，属于高风险跳切；要么做到精确动作/首尾帧匹配，要么主动改用对比切或中性桥。

长画外音不能持续使用说话人物的正面可读嘴部镜头。文字上的“嘴唇完全闭合”只是一层约束；还必须通过背面、过肩、侧面遮挡、手部/道具、视线目标或环境镜头降低模型自动口型风险。

同一角色再次出现时，提示词必须重申身份、服装、发型、湿度/污渍状态和当前情绪后的身体状态。每段只保留真正可见且需要锁定的参考主体，通常 1–4 个，绝不把全部资产通用附加到每条提示词。

同一重要道具再次出现时，也必须按 `PROP_STATE_CHAIN` 重申当前持有人、位置、朝向/开合/折叠/损坏等状态，以及本片段会发生的状态变化。上传参考图或在 `subject_definitions` 中定义道具，不等于模型会继承前一独立片段的状态。

## 五、HTML 输出与强制校核

H3 HTML 的每个片段必须展示：

- 片段编号、单一场景、情绪/行动单元、总时长；
- 实际使用的参考资产；
- 片段衔接方案；
- 全场 `SCENE_SHOT_LADDER` 与每个相邻片段的 `CLIP_BOUNDARY_LEDGER`；
- 内部镜头表：时码、时长、景别/机位、可见行动、原文台词/旁白、字数估时；
- 本片段拥有的 `source_beat_id`、可见动作最低时长，以及涉及的连续道具开场状态→变化→落点；
- 可复制的英文 H3 主提示词与结构、标签、台词完全同步的中文编辑镜像。
- 全片/当前范围的声明时长、打包总时长、差值和逐场小计。

输出前逐项验证：

1. 段时长为各内部镜头时长之和；文戏默认 10–15 秒，5–9.99 秒必须有允许的例外理由，绝不得超过 15.00 秒；
2. 镜头数与时长由完整戏剧单元决定；10 秒 2–3 镜、12 秒 3–4 镜、15 秒 3–5 镜仅作密度校核，完整连续单镜和多镜单元内 0.5–2.5 秒必要短镜不得因此被判错；
3. 每一处切镜都新增信息或转移情绪视角；若没有，合并镜头；
4. 片段不跨场景；
5. 台词原文、顺序、说话者和可听见内容完全一致；
6. 每一处片段边界都给出连续性锚点；
7. 每段引用的参考资产均真实可见且实际需要。
8. 每个原剧本 `SOURCE_BEAT` 都映射到一个 `SHOT_BEAT`、一个 `H3_UNIT`，并在英文和中文复制提示词中有可执行证据；空镜、入场、可见文字或后期节点的干净底图/时机/反应、表演动作不得遗漏；
9. 每条连续道具状态链在所有出现位置闭合，片段边界处的持有人、位置和状态一致；
10. 压缩后仍满足完整口播时间线和可见动作时间线，中文文戏有效台词不超过 40 字并尽量落在对应时长建议区间；若只能靠概括动作、极速朗读或假定模型自行继承道具状态才能放入，则必须重新拆分。
11. 所有片段总和与 `DECLARED_RUNTIME` 对账；若超出 5% 且未获得用户明确决策，则校核失败。
12. 相邻片段数为 N 时存在 N-1 条边界台账，每条有唯一合法策略、明确切点和两侧首尾画面证据；
13. 无意外同轴相近景别缩放、视线/情绪重置或未展示的道具动作跳变；
14. 画外音的画面构图本身降低口型风险，而非只依赖文字指令；
15. 已区分请求、支持与实际成片时长，并确认真实稳定头尾余量；若用户提供视频，已完成逐边界接触表验收。

任何一项不通过，必须先重新编排 `H3_UNIT_BLUEPRINT`，不得直接输出“合规”标签。
