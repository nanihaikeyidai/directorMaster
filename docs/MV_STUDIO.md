# Director Master MV 制作工作台

## 目标

把一首完整歌曲整理为可直接进入 MiniMax H3 视频生产的连续片段包。每段必须保留完整唱句、时长不超过 15 秒，并携带音频文件、时间范围、镜头说明、素材序号和结构化 H3 提示词。

页面入口：`http://localhost:3000/mv`

## 工作流目录与配置

MV 工作流统一归档在 `workspace/workflows/mv/`，分为两个子目录：

```text
workspace/workflows/mv/
├─ local/   # 本地 ComfyUI / MiniMax H3 导演台 JSON
└─ cloud/   # RunningHub API JSON
```

页面右上角“工作流配置”提供本地/云端两个页签。文件选择会把 JSON 副本导入对应目录，目录中的文件会自动列出，可直接切换。云端页签同时保存 RunningHub 工作流 ID；API JSON 本身通常不携带这个 ID，需从 RunningHub API 页面复制填写。当前默认云端模板是 `minimax_h3_remix_ref2va_dual_sampling_api.json`。

页面、CLI 和项目文件继续使用统一的 `segments / pictures / audios / settings` 输入协议。`vite-plugins/runninghub-workflow-adapters.ts` 在提交前识别工作流类型并完成转换：肥猴 Remix 写入 12 个媒体槽、提示词、时长、分辨率、FPS、8/4 步双采样和原音频开关；旧 ReferenceToVideo 和 Director 工作流继续走各自适配器。Remix API（`FeiHouEasyH3RH`）支持 9 张图片与 3 条音频参考。肥猴工作流返回多个视频时，优先级为人脸精修成片、第二采样成片、第一采样成片。

## 推荐流程

1. 上传 WAV、MP3、FLAC、M4A、OGG 或 AAC 音乐，系统使用 FFprobe 验证音轨并在 `workspace/mv/<项目>/source` 保存源文件。
2. 先选择轨道工具：`V 播放定位`只操作白色播放头；`C 编辑切点`只操作橙色切线；`T 音频边界`只操作青色 IN/OUT。模式隔离防止重叠线条互相抢操作。
   - 音频轨道支持鼠标滚轮缩放（100%–2400%）；缩放以鼠标所在时间点为中心，放大后使用轨道下方横向滚动条浏览远端时间。
3. “智能建议切点”会在每个 15 秒窗口末端寻找低能量停顿。它只负责初筛，不能代替人工试听。
4. 根据波形和试听完成切割。切点可以在当前音频范围内自由拖动；超过 15 秒的分段在下方标尺显示红色时长，但不会阻止继续调整。生成和导出前仍执行 15 秒硬校验。
   - 空格键只负责播放/暂停，不会创建切点。
   - 在波形上单击右键，通过菜单把当前指针位置添加为切点。
5. 分别拖入人物素材和场景素材，合计最多 9 张。素材可以上移、下移、编辑两句内说明或二次确认删除；当前顺序固定映射为 `<Picture 1>` 至 `<Picture 9>`，音频分段固定映射为 `<Audio 1>`。
6. 填写全局成员顺序、舞台、灯光、服装、表演与队形规则，点击“生成提示词”。页面下方按片段显示可编辑、可复制、可试听核对的 MiniMax H3 六段式最终提示词。
7. 审核提示词后，再导出逐段 WAV、`segments.json` 和最终提示词。

### 替换音乐与新建项目

- 当前项目点击“替换音乐”后，上传的新音频会写回同一个项目 ID；人物/场景素材、素材描述、全局 MV 规则和工作流配置继续沿用。旧切点、分段提示词和当前生成状态会清空，因为它们绑定的是旧音频时间轴。
- 打开项目后可以直接把新的音乐文件拖到 `SOURCE TRACK` 音轨面板；页面会阻止浏览器打开文件链接，并按“替换音乐”流程处理。
- 替换不会删除旧源音频、旧分段 WAV、旧成片或素材文件；替换前的 `project.json` 会备份到 `history/music-replacements/`，方便追溯。
- 点击“新建项目（清空素材）”才会开始一个全新的空素材项目；旧项目仍保留在“历史项目”中，不会被删除。

如果需要无人值守出片，可点击“ 一键云端出完整 MV ”：系统会在没有手动切点时自动寻找低能量切点，生成标准提示词，按顺序串行调用 RunningHub MV 工作流；全部视频下载后，以原始音乐为唯一音轨自动合成完整 MV。自动流程仍会阻止缺少人物/场景素材、波形未准备好或片段超过 15 秒的项目。

## 键盘与边缘场景

- `Space`：播放/暂停。切点通过“在播放头裁切”或波形右键菜单添加。
- `V`：播放定位；`C`：编辑切点；`T`：编辑音频入点/出点。
- `Ctrl+Z` / `Cmd+Z`：撤销最近一次新增、移动或删除切点，最多保留 50 步。
- `Delete` / `Backspace`：删除选中的切点；光标在输入框时不会拦截文本编辑。
- 切点距离首尾不足 0.25 秒会被忽略；重复切点会被合并。
- 导出层再次用真实音频时长校验，任何片段超过 15 秒都会整体阻止导出。
- 纯间奏应标记为“间奏段”，提示词会禁止模型虚构歌声或台词。
- 自动切点基于声音能量，遇到延音、混响、无停顿说唱或跨句换气时必须人工拖动切点。

## 提示词一致性

提示词版本签名同时包含切点、每段歌词/导演词、人物与场景素材描述、全局导演规则、当前音轨时长和模板版本。任一输入发生变化后，已生成提示词会标记为“需重新生成”，不会被误认为仍可直接出片；重新切割后点击“生成标准提示词”会按最新分段时长重新生成整套提示词。

## 输出结构

```text
workspace/mv/<项目>/
├─ project.json
├─ assets/
│  ├─ 人物/
│  └─ 场景/
├─ source/
│  └─ 原始音乐文件
└─ segments/
   ├─ segment-01_0.000-12.340.wav
   ├─ segment-02_12.340-26.100.wav
   └─ segments.json
```

`segments.json` 是 UI、CLI 和 Agent 之间的稳定交接格式。每段记录 `start`、`end`、`duration`、`lyrics`、`direction`、`prompt`、`fileName` 和绝对 `path`。

人物与场景素材记录在 `project.json.visualAssets`，数组顺序就是 H3 引用顺序。人物生成身份 `<Subject N>`，场景生成环境 `<Subject N>`，两者通过同号 `<Picture N>` 定义来源。导出前至少需要一张人物素材和一张场景素材。

## CLI

```powershell
npm run director -- mv-cut -- --audio "D:\music\song.wav" --project "MV-01" --cuts 12.34,26.10,40.50 --notes "D:\music\MV-01-segments.json" --people "D:\music\人物" --scenes "D:\music\场景"
```

`--notes <json>` 是可选的按段导演说明；省略时根据项目素材和默认 MV 规则生成：

```json
[
  { "kind": "vocal", "lyrics": "第一句完整唱词", "direction": "主唱近景，副歌前缓慢推进" },
  { "kind": "instrumental", "lyrics": "", "direction": "四人队形切换，镜头绕行半圈" }
]
```

CLI 与页面执行相同的 15 秒硬校验，并生成相同目录结构。页面提供更适合人工听辨和微调的波形交互；CLI 适合 Agent 已经拿到确定时间点后的批量生产。

## 分段视频生成

- 每个提示词卡片提供“本地生成”和“云端生成”。本地模式使用当前已启动的 ComfyUI 与 MiniMax H3 导演台工作流，不会启动新的 ComfyUI。
- 提示词审核区顶部提供两种批量生成入口。用户可以先勾选片段，再提交任务。
- 本地批量把所选连续片段编译进同一个导演台任务，并对相邻片段开启段间引导；非相邻选择不会错误建立连续关系。
- 云端批量使用指定的 RunningHub 导演台工作流，严格串行执行：当前片段完成或失败后，才处理下一片段。
- 每个片段显示准备、排队、生成、成功或失败状态；成功后可直接播放或打开成片。
- 云端片段全部完成后，服务端使用 FFmpeg 按片段顺序拼接视频，并从项目源音频重新封装音轨，避免使用模型生成的替代音乐。

## H3 提示词约束

每段提示词按 `subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music` 六个区域生成。歌词保留原文并放入 `<d>...</d>`，音频被声明为权威节奏与演唱来源；默认禁止替换音乐、虚构台词、字幕、歌词字卡、身份漂移和跨段空间跳变。

### 声音驱动演唱

- `<Audio 1>` 必须来自当前 SOURCE TRACK 的实时导出，不读取旧分段缓存；文件名包含源音频版本号，服务端还会校验 `sourcePath`、源版本与导出时长。
- 全局规则中的“原音乐人声首次进入”从未加空白的原音乐 0 秒开始计时；系统自动叠加项目的前置空白。
- 人声进入前，主唱保持自然闭口，只允许候场造型、呼吸、眼神、握麦或乐器预备动作。听到首个真实音节后才开始口型，停唱和间奏期间立即自然闭口。
- 每次增加前置空白都会生成新的 SOURCE TRACK 版本、平移切点和范围、清空旧提示词签名。生成前重新导出 WAV，导演台与 RunningHub 的 `<Audio 1>` 都引用这个新文件。
